# esbuild-coffeescript

An esbuild plugin that compiles `.coffee` and `.litcoffee` files with CoffeeScript 2 and hands the JavaScript to esbuild. It's published to npm as `esbuild-coffeescript`.

## Commands

- `pnpm install`: installs dependencies. Use pnpm 12 (pinned in `packageManager`), never `npm`/`yarn`.
- `pnpm test`: runs the Vitest suite once. It must pass before you finish.
- `pnpm test test/esbuild-coffeescript.test.ts -t "rebuild"`: runs a single file, or the tests whose names match.
- `pnpm typecheck`: runs `tsc` against `tsconfig.json`, which checks `src/` and `test/` and emits nothing.
- `pnpm build`: runs `tsc -p tsconfig.build.json` and emits `dist/` from `src/` only.
- `pnpm check`: runs `ultracite check` (oxfmt format check plus type-aware oxlint).
- `pnpm fix`: runs `ultracite fix`, which auto-fixes formatting and lint errors.
- `pnpm run ci`: runs check, then typecheck, then test, then build. This is exactly what CI runs.
- `pnpm changeset`: records a release note and semver bump in `.changeset/`.

None of these commands need network access or credentials.

## Stack

- **Node 24.21** (`.nvmrc`), ESM only (`"type": "module"`, `module: nodenext`). Relative imports in TypeScript use the `.js` extension: `import plugin from "../src/index.js"`.
- **TypeScript 7.0** (the native `tsc`).
- **esbuild `>=0.25.9`** is a peer dependency; the dev pin is `^0.28.2`.
  - Plugin `filter` regexes run on Go's RE2 engine, not JavaScript's: no lookbehind, no backreferences, and no regex flags. esbuild turns a `u` flag into `(?u)`, which RE2 rejects, so the plugin fails at runtime. That is why `require-unicode-regexp` is turned off for `src/**`.
  - `PartialMessage.location.line` starts at 1 and `column` starts at 0. CoffeeScript's `first_line` starts at 0, so add 1.
- **CoffeeScript 2.7** has types from `@types/coffeescript`, which is a runtime dependency because `dist/index.d.ts` imports its `Options`. Those types don't include `literate`; `CompileOptions` in `src/index.ts` adds it.
- **Vitest 5** for tests.
- **Ultracite 8** configures oxlint and oxfmt. There's no Biome, ESLint or Prettier. The formatter decides style: double quotes, 2-space JSON.

## Structure

- `src/index.ts`: the entire plugin. Its default export is `coffeeScriptPlugin`; it also exports the `Options` type.
- `test/esbuild-coffeescript.test.ts`: the test suite. Every test runs a real `esbuild.build` or `esbuild.context`.
- `test/input/`: test input files. Tests assert the exact error position in `invalid-coffee.coffee` (line 3, column 8), so keep them in sync with that file.
- `.changeset/`: pending release notes. `config.json` holds the changesets config.
- `CHANGELOG.md`: generated by changesets. Never edit it by hand.
- `dist/`: build output, gitignored. Never edit or commit it.
- `oxlint.config.ts`, `oxfmt.config.ts`: Ultracite presets plus the `src/**` regex override.
- `.github/workflows/`: `master.yml` runs `pnpm run ci`; `release.yml` runs changesets publishing.
- `.github/hooks/ultracite.json`: an agent hook that runs `ultracite fix --hook` after edits.

## Code style

The linter is strict (Ultracite core, vitest and anti-slop presets). Write code that passes `pnpm check` instead of suppressing rules:

- Don't use `as` casts on unknown values. Narrow them with a type guard (a function returning `value is T`). `typeof` checks and `unknown` parameters are only allowed inside type guards.
- Object literal keys go in sorted order. Leave a blank line before a statement that follows a multi-line one.
- Use `"utf-8"`, not `"utf8"`. Name catch variables `error`. Use `replaceAll` with a string instead of `replace(/x/g)`.
- Tests go inside `describe(fn, ...)` and use `it`. Never call `expect` inside a branch or a `catch`. Assert rejections with `await expect(p).rejects.toMatchObject(...)`.

```ts
// Good: the type guard proves the shape, so `location` is typed without a cast
const isCoffeeScriptSyntaxError = (
  error: unknown
): error is CoffeeScriptSyntaxError => {
  if (!(error instanceof SyntaxError && "location" in error)) {
    return false;
  }

  const { location } = error;

  return (
    typeof location === "object" &&
    location !== null &&
    "first_line" in location &&
    typeof location.first_line === "number"
  );
};

// Bad: unchecked assertion, unsorted keys, and a 0-based line given to esbuild
const e = err as CoffeeScriptError;
return { text: e.message, location: { line: e.location.first_line } };
```

## Git workflow

- Branch off `master` (for example `feature/<topic>`) and open a PR to `master`. Don't push to `master` directly.
- Commits follow [Conventional Commits](https://www.conventionalcommits.org/): `type(scope): description`, 72 characters max, imperative mood. Add `!` and a `BREAKING CHANGE:` footer for breaking changes.
- A lefthook pre-commit hook runs `ultracite fix` on staged files.
- Every user-facing change needs a changeset (`pnpm changeset`). Removing an `Options` field or changing reported error locations counts as **major**. Tooling-only changes need no changeset.
- Releasing: merging to `master` makes `release.yml` open a "Version Packages" PR. Merging that PR publishes to npm.

## Boundaries

**Always:** run `pnpm run ci` before finishing. Add a test for any behavior change, using real esbuild builds. Update `README.md` when `Options` or the plugin's behavior changes.

**Ask first:** adding or upgrading a runtime `dependency` (it ships to every user), changing the `esbuild` peer range, changing CI workflows or the release setup, removing or renaming anything exported from `src/index.ts`.

**Never:** suppress lint errors (`oxlint-disable`, `@ts-ignore`, `@ts-expect-error`, unjustified `as` casts) to get `pnpm check` passing. Delete or weaken a failing test to make the suite pass. Edit `CHANGELOG.md` or `dist/`. Commit secrets, or the `NPM_TOKEN`/`GH_TOKEN` values. Force-push `master`.
